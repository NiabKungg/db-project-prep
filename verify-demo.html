⭐ ไฟล์ 5 · Script ตรวจสอบอาจารย์ — เวอร์ชันแก้ให้รันได้จริงบน Oracle

⚠️ ต้นฉบับอาจารย์มีบั๊กที่ต้องอธิบายหน้างานได้

ต้นฉบับใช้ USER_TABLES.OWNER — แต่ USER_TABLES ไม่มีคอลัมน์ OWNER จริง รันตรง ๆ จะได้ ORA-00904: "USER_TABLES"."OWNER": invalid identifier — เพราะ OWNER มีเฉพาะ ALL_TABLES/DBA_TABLES ซึ่งต้องใช้สิทธิ์สูง — เราจึงแก้เป็น USER AS OWNER (USER = ฟังก์ชันคืนชื่อ schema ปัจจุบัน ผลเหมือนกันเพราะ USER_TABLES = ตารางที่ User ตัวเองเป็นเจ้าของอยู่แล้ว)

oracle_5_verify.sql 
-- ตารางของ Database User + Constraint ทั้งหมด
SELECT USER_TABLES.TABLE_NAME, TABLESPACE_NAME, USER AS OWNER,
       CONSTRAINT_NAME, CONSTRAINT_TYPE, USER_CONSTRAINTS.TABLE_NAME
FROM USER_TABLES LEFT OUTER JOIN USER_CONSTRAINTS
  ON (USER_TABLES.TABLE_NAME = USER_CONSTRAINTS.TABLE_NAME)
ORDER BY USER_TABLES.TABLE_NAME, CONSTRAINT_TYPE, CONSTRAINT_NAME;

-- เช็คเพิ่มเติม: SEQUENCE ของโปรเจกต์ (SEQUENCE ไม่แสดงใน USER_TABLES)
SELECT SEQUENCE_NAME, LAST_NUMBER FROM USER_SEQUENCES ORDER BY SEQUENCE_NAME;

-- เช็คเพิ่มเติม: Stored Procedure ของโปรเจกต์ (VALID = compile ผ่าน)
SELECT OBJECT_NAME, STATUS FROM USER_OBJECTS
WHERE OBJECT_TYPE = 'PROCEDURE' AND OBJECT_NAME LIKE 'SP_%'
ORDER BY OBJECT_NAME;

ความต่างจากชุด Part I: เพิ่ม 2 query เสริม — ตรวจ SEQUENCE 7 ตัว (ไม่โผล่ใน USER_TABLES) และตรวจว่า Procedure ทุกตัว STATUS = VALID (compile ผ่าน ไม่มี INVALID ติดค้าง)

Part II — Smart Bus Bell (9 ข้อ — จากประสบการณ์ deploy จริง)

คำถามคำตอบสั้น
ทำไมมี Junction Table?ความสัมพันธ์ N:M ใน ER แปลงเป็นตารางกลาง เช่น VEHICLE_BELL_REQUEST (PK = คู่ FK ทั้งสอง) — 1 แถว = 1 คู่ "กริ่งนี้→รถนี้"
ทำไม IOT_BOX PK เป็น (VEHICLE_ID, BOX_ID)?Weak Entity ผูกกับรถแบบ Identifying Relationship → composite PK = PK เจ้าของ + Partial Key
Transaction Processing อยู่ตรงไหน?SP_PRESS_BELL = 3 DML (INSERT BELL_REQUEST + INSERT junction + MERGE สถิติ) ใน 1 transaction — สำเร็จ COMMIT / พลาด ROLLBACK ทั้งหมด
MERGE ทำอะไร?Upsert สถิติ: ยังไม่มีสถิติ (รถ, วันนั้น) → INSERT count=1 / มีแล้ว → UPDATE +1 (อาศัย UNIQUE รถ+วัน)
Business Rule ในโค้ดมีอะไร?กดกริ่งได้เฉพาะ PASSENGER (ORA-20001) · ยืนยันลงรถ/ยกเลิกได้เฉพาะสถานะ SENDING (SQL%ROWCOUNT=0 → ORA-20002/-20004)
CONSTRAINT_TYPE ในผลลัพธ์คืออะไรบ้าง?P=PK, R=FK, C=Check/NOT NULL, U=Unique — และ SYS_Cxxxx = NOT NULL ที่ Oracle ตั้งชื่อให้อัตโนมัติ
ทำไมมี SEQUENCE?Oracle 10g ไม่มี AUTO_INCREMENT → ใช้ SEQUENCE.NEXTVAL สร้าง key (7 ตัวของโปรเจกต์)
จำนวนคนบนรถอยู่ไหน?เป็น Derived Attribute ตาม ER → ไม่เก็บคอลัมน์ ต้องคำนวณจากแหล่งอื่น (ตัวนับ IoT/แอปคนขับ)
ข้อจำกัด Oracle 10g ที่เจอ?① SEQ.CURRVAL ใน PL/SQL → PLS-00357 แก้ด้วย RETURNING INTO ② ไม่มีสิทธิ์ CREATE VIEW → ORA-01031 แก้ด้วย WITH clause ③ USER_TABLES.OWNER ไม่มีจริง → ORA-00904 แก้ด้วย USER AS OWNER

คำถามคำตอบสั้น
ทำไมมี FK / NOT NULL / CHECKFK = อ้างอิงความถูกต้องข้ามตาราง · NOT NULL = ข้อมูลจำเป็น · CHECK = จำกัดค่าตามกฎธุรกิจ (สถานะ 8 ค่า / ช่องทาง 3 ช่อง)
Transaction อยู่ตรงไหนSP_DECIDE_APPROVAL: บันทึกผล + ลงนาม + กระจาย + แจ้งเตือน ใน Transaction เดียว — ผิดพลาด ROLLBACK ทั้งหมด (Atomicity)
ถ้าตีกลับ (REJECTED) เอกสารไปไหนสถานะ REJECTED (เหตุผลใน APPROVALS.REASON) → ธุรการแก้ร่าง → ส่งซ้ำผ่าน SP_SUBMIT_DOC (ยอมรับ DRAFT/REJECTED) — ตาม XOR Gateway
Trigger ทำอะไรTRG_DOC_STATUS_LOG บันทึก Audit Trail ทุกครั้งที่สถานะเปลี่ยน (OLD ≠ NEW) — รองรับ UC03 + BR-Memo-103
Sequence ทำอะไรสร้างรหัสอ้างอิงอัตโนมัติ เช่น Doc ID (ตาม To-Be "จัดเก็บ + ออกรหัสอ้างอิง") — SEQ_DOC เริ่ม 5001
ป้องกันยืนยันซ้ำยังไงUNIQUE (DOC_ID, EMP_ID) + EXCEPTION DUP_VAL_ON_INDEX → ORA-20010 — กันซ้ำ 2 ชั้น
SLA 24 ชม. ทำงานยังไงSP_CHECK_SLA_REMIND: เกิน 24 ชม. และยังมีคนไม่ยืนยัน → INSERT NOTIFICATIONS type REMINDER เฉพาะคนที่ยังไม่อ่าน

JOIN มากสุดกี่ตารางQ1 = 6 ตาราง (DOCUMENTS + EMPLOYEES ผู้ร่าง + ROLES + APPROVALS + EMPLOYEES ผู้อนุมัติ + SIGNATURES) — LEFT JOIN 3 ตัวให้เอกสารยังไม่พิจารณาไม่หาย

🌱 Q&A พื้นฐานเฉพาะ "คนที่ไม่มีพื้นฐาน SQL" (โดนจิ้มแบบง่าย ๆ ต้องตอบลื่น)

อาจารย์มักทดสอบความเข้าใจจริงด้วยคำถามพื้นฐานสุด ๆ — คนพื้นฐานดีที่ตอบข้อนี้ลื่นจะดู "เข้าใจจริง" กว่าคนท่องโค้ดเป็นนกแก้ว:

คำถามแบบจิ้มง่ายคำตอบแบบคนเข้าใจจริง
"SELECT คืออะไร เอาไปทำไม"คำสั่ง "ขอดูข้อมูล" — ไม่แก้ไม่ลบอะไร ดึงมาแสดงเท่านั้น เช่น SELECT * FROM USERS = ขอดูตารางผู้ใช้ทั้งหมด
"* บนจอนี้หมายความว่าอะไร""ทุกคอลัมน์" — ถ้าอยากได้เฉพาะบางคอลัมน์ก็พิมพ์ชื่อคอลัมน์แทน *
"แถว (Row) กับคอลัมน์ (Column) ต่างกันยังไง ชี้ให้ดูในผลที่จอ"คอลัมน์ = หัวข้อแนวตั้ง (USER_ID, FULL_NAME) · แถว = ข้อมูล 1 ชิ้นจริงแนวนอน (สมหญิง 1 บรรทัดทั้งบรรทัด)
"PK กับ FK พูดง่าย ๆ คืออะไร"PK = เลขบัตรประชาชนของแถว (ไม่ซ้ำ ไม่ว่าง) · FK = คอลัมน์ที่เขียน "รหัสของตารางอื่น" ไว้ผูกความสัมพันธ์ (USERS มี ROLE_ID ชี้ไป USER_TYPE)
"WHERE ใช้ทำอะไร ถ้าลบออกจะเป็นยังไง"กรองเฉพาะแถวที่เงื่อนไขจริง — ลบออกได้ "ทุกแถวทั้งตาราง"
"COMMIT กับ ROLLBACK ต่างกันยังไง"COMMIT = บันทึกถาวร · ROLLBACK = ย้อนยกเลิกสิ่งที่ทำในรอบนี้ทั้งหมด — ระบบนี้ใช้หลัก "ทำครบทุกขั้นถึง COMMIT พังกลางทาง ROLLBACK ทันที"
"เลข 1, 2, 3 ที่โผล่ทั่วจอมาจากไหน"จาก SEQUENCE (เครื่องนับอัตโนมัติ เริ่มที่ 1) — เช่น USER_ID 1-4 = admin, วิชัย, สมหญิง, มานะ · ไม่มีใครพิมพ์เอง
"อ่านแถวนี้บนจอให้ฟังหน่อย" (จิ้มแถวไหนก็ได้)ใช้สูตร 3 ประโยคด้านล่าง — ฝึกจนพูดได้กับแถวสุ่มใด ๆ

🧠 สูตรตอบ "อ่านโค้ด/ผลบนจอให้ฟัง" — 3 ประโยคตายตัว (ใช้ได้ทุกแถว ทุกก้อนโค้ด)

  1. "บรรทัดนี้ทำอะไร" — แปลโค้ดเป็นไทยตรง ๆ ("แถวนี้บอกว่าตาราง BELL_REQUEST มี constraint ชื่อ CK_BELL_STATUS ชนิด C ที่จำกัดสถานะ 3 ค่า")
  2. "ทำไมจึงมี" — เหตุผลธุรกิจ ("สถานะต้องเดินตามโจทย์ กันใส่ค่ามั่ว")
  3. "ถ้าไม่มีจะเกิดอะไร" — ผลเสีย ("ใส่ 'ส่งแล้ว' แบบพิมพ์ผิดก็ผ่าน ระบบอ่านไม่รู้เรื่อง")

ซ้อมสุ่มแถวตอบ 3 ประโยคให้คล่องก่อนเข้าห้อง — อาจารย์จิ้มตรงไหนก็รอด
