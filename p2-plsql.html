🚦 PL/SQL Transaction Processing — Procedure 4 ตัว + Demo Block ครอบโจทย์หลัก "กดกริ่งลงรถ"

SP 4 ตัวRETURNING INTO · MERGE · SQL%ROWCOUNTไฟล์ 3 (Oracle 10g R2)

① อาจารย์ต้องการอะไร (โจทย์ข้อนี้)

"2- เขียน PL/SQL ตามโจทย์หลักของระบบงาน (Transaction Processing)" — โจทย์หลักของระบบนี้คือ: กดกริ่งลงรถ → ส่งสัญญาณถึงรถ → อัปเดตสถิติ ใน transaction เดียว — SP_PRESS_BELL คือคำตอบตรง ๆ: 3 DML + COMMIT/ROLLBACK ใน Procedure เดียว · สคริปต์ deploy บน server แล้ว วันสอบรับซ้ำและซักถาม — จุดที่อาจารย์ซักหนักคือ ข้อจำกัด Oracle 10g 3 ข้อด้านล่าง (เจอจริงตอน deploy)

⚠️ ข้อจำกัด Oracle 10g 3 ข้อ — "จุดโปรดของอาจารย์" ที่เจอจริงบน server (ตอบได้ = ผ่านใหญ่)

ข้อจำกัดอาการถ้าทำผิดวิธีแก้ในสคริปต์ของเรา
1. ห้ามใช้ SEQ.CURRVAL ใน PL/SQL expression (10g เท่านั้น — 11g+ ทำได้)PLS-00357ใช้ INSERT ... RETURNING id INTO ตัวแปร คว้า ID ที่เพิ่ง insert กลับมา — ใช้ใน SP_PRESS_BELL และ SP_SEND_DIGITAL_SIGNAL
2. Account ไม่มีสิทธิ์ CREATE VIEWORA-01031: insufficient privilegesรายงาน 3 ใช้ WITH ... AS (Subquery Factoring) สร้าง "view ชั่วคราวใน query เดียว" แทน — ผลเหมือนกัน
3. USER_TABLES ไม่มีคอลัมน์ OWNER (script ต้นฉบับอาจารย์รันไม่ผ่าน)ORA-00904: "USER_TABLES"."OWNER": invalid identifierไฟล์ 5 แก้เป็น USER AS OWNER (USER = ฟังก์ชันคืนชื่อ schema ปัจจุบัน · OWNER มีจริงเฉพาะ ALL_TABLES/DBA_TABLES ซึ่งต้องสิทธิ์สูง)

เกร็ดเสริม: Oracle 10g ไม่มี AUTO_INCREMENT → ใช้ SEQUENCE.NEXTVAL · ไม่มี ENUM → ใช้ VARCHAR2 + CHECK

🧠 พื้นฐานที่ต้องพูดให้ออกก่อนรันโค้ด

Transaction ของระบบนี้อยู่ตรงไหน — ตอบพร้อมเดินให้ดู

SP_PRESS_BELL = 1 transaction ครบ 3 DML: ① INSERT BELL_REQUEST (สถานะ SENDING) → ② INSERT VEHICLE_BELL_REQUEST (ส่งสัญญาณถึงรถผ่าน junction) → ③ MERGE ALERT_STATISTICS (สถิติรถวันนี้ +1) → สำเร็จทั้งหมดจึง COMMIT · พลาดขั้นไหน ROLLBACK ทั้งหมด (Atomicity) — ข้อมูลไม่มีวันครึ่ง ๆ เช่น "กดแล้วแต่รถไม่รู้"

RETURNING ... INTO — INSERT เสร็จปั๊บ ดึงค่าคอลัมน์ที่เพิ่งใส่ (เช่น ID จาก SEQUENCE) กลับมาเก็บในตัวแปร — ทางออกของ 10g แทน SEQ.CURRVAL

MERGE (Upsert) — "ถ้ามีแถวนี้อยู่แล้ว → UPDATE / ถ้ายังไม่มี → INSERT" ทำในคำสั่งเดียว (WHEN MATCHED / WHEN NOT MATCHED)

SQL%ROWCOUNT — นับว่าคำสั่งล่าสุด (UPDATE/DELETE) กระทบไปกี่แถว — = 0 แปลว่าไม่เจอแถวที่ต้องการ → โยน error เอง

%TYPE — ให้ตัวแปร/พารามิเตอร์มีชนิดตามคอลัมน์จริง เช่น P_USER_ID IN BELL_REQUEST.USER_ID%TYPE — แก้ DDL แล้วโค้ดไม่พัง

Parameter Binding — SP ทุกตัวรับค่าผ่านพารามิเตอร์ ไม่ต่อสตริง SQL (กัน SQL Injection — โจทย์ซักถามได้)

ก้อนที่ 1 · SP_PRESS_BELL — Transaction หลักของระบบ ⭐

oracle_3_plsql.sql · PROCEDURE 1 
-- ----------------------------------------------------------------------------
-- SP_PRESS_BELL : ผู้โดยสารกดกริ่งลงรถ (1 transaction = 3 DML + COMMIT/ROLLBACK)
-- ----------------------------------------------------------------------------
CREATE OR REPLACE PROCEDURE SP_PRESS_BELL (
  P_USER_ID     IN  BELL_REQUEST.USER_ID%TYPE,       -- ผู้กดกริ่ง
  P_VEHICLE_ID  IN  VEHICLE.VEHICLE_ID%TYPE,         -- รถเป้าหมาย
  P_BELL_REQ_ID OUT BELL_REQUEST.BELL_REQ_ID%TYPE   -- คืน ID รายการที่สร้าง
) IS
  V_ROLE_NAME USER_TYPE.ROLE_NAME%TYPE;
BEGIN
  -- (1) Business Rule: ต้องเป็น PASSENGER เท่านั้น
  SELECT ut.ROLE_NAME INTO V_ROLE_NAME
  FROM USERS u JOIN USER_TYPE ut ON ut.ROLE_ID = u.ROLE_ID
  WHERE u.USER_ID = P_USER_ID;

  IF V_ROLE_NAME <> 'PASSENGER' THEN
    RAISE_APPLICATION_ERROR(-20001,
      'ผู้กดกริ่งต้องเป็น PASSENGER เท่านั้น (ได้บทบาท: '||V_ROLE_NAME||')');
  END IF;

  -- (2) สร้างรายการกดกริ่ง (สถานะเริ่ม SENDING)
  -- หมายเหตุ: Oracle 10g ห้ามใช้ SEQ.CURRVAL ใน PL/SQL expression (ทำได้เฉพาะ 11g+)
  --           จึงใช้ RETURNING INTO เพื่อคว้า ID ที่เพิ่ง insert กลับมาแทน
  INSERT INTO BELL_REQUEST (BELL_REQ_ID, USER_ID, REQ_TIME, NOTIFY_STATUS)
  VALUES (SEQ_BELL_REQ.NEXTVAL, P_USER_ID, SYSDATE, 'SENDING')
  RETURNING BELL_REQ_ID INTO P_BELL_REQ_ID;

  -- (3) ส่งสัญญาณถึงรถเป้าหมาย (ผ่าน Junction Table ของ N:M)
  INSERT INTO VEHICLE_BELL_REQUEST (BELL_REQ_ID, VEHICLE_ID, SENT_AT)
  VALUES (P_BELL_REQ_ID, P_VEHICLE_ID, SYSDATE);

  -- (4) อัปเดตสถิติการแจ้งเตือนของรถ (Upsert ด้วย MERGE)
  MERGE INTO ALERT_STATISTICS a
  USING (SELECT P_VEHICLE_ID AS VID, TRUNC(SYSDATE) AS D FROM DUAL) s
  ON (a.VEHICLE_ID = s.VID AND a.STAT_DATE = s.D)
  WHEN MATCHED THEN UPDATE SET a.ALERT_COUNT = a.ALERT_COUNT + 1
  WHEN NOT MATCHED THEN
    INSERT (STAT_ID, VEHICLE_ID, STAT_DATE, ALERT_COUNT)
    VALUES (SEQ_ALERT_STAT.NEXTVAL, s.VID, s.D, 1);

  COMMIT;                                   -- สำเร็จทั้งหมดจึง COMMIT
EXCEPTION
  WHEN OTHERS THEN
    ROLLBACK;                               -- ผิดพลาด = ยกเลิกทั้ง transaction
    RAISE;                                  -- ส่ง error กลับผู้เรียก
END;
/
  • ขั้น (1) — JOIN USERS×USER_TYPE ดึงชื่อบทบาทของคนกด ถ้าไม่ใช่ PASSENGER → -20001 (Business Rule ที่โจทย์ระบุ) · <> อ่านว่า "ไม่เท่ากับ"
  • ขั้น (2) — INSERT สถานะเริ่ม SENDING + RETURNING BELL_REQ_ID INTO P_BELL_REQ_ID — คว้า ID ใหม่ทันที (ทางแก้ Oracle 10g)
  • ขั้น (3) — เขียนลง Junction Table = "สัญญาณถึงรถ" — คือการใช้ตารางกลาง N:M ที่ออกแบบไว้จริง
  • ขั้น (4) — MERGE: เทียบ (รถ, วันนี้) กับ ALERT_STATISTICS มีแถวอยู่แล้ว → นับ +1 / ยังไม่มี → INSERT เริ่มที่ 1 · TRUNC(SYSDATE) = ตัดเวลาเหลือแค่วันที่
  • COMMIT เดียวจบ 3 DML — WHEN OTHERS → ROLLBACK + RAISE: พังกลางทางย้อนทุกอย่าง (Atomicity) และไม่กลืน error

ก้อนที่ 2 · SP_SEND_DIGITAL_SIGNAL — กริ่งดิจิตอลประจำรถ

oracle_3_plsql.sql · PROCEDURE 2 
CREATE OR REPLACE PROCEDURE SP_SEND_DIGITAL_SIGNAL (
  P_USER_ID     IN  DIGITAL_BELL_SIGNAL.USER_ID%TYPE,
  P_VEHICLE_ID  IN  VEHICLE.VEHICLE_ID%TYPE,
  P_SIGNAL_ID   OUT DIGITAL_BELL_SIGNAL.SIGNAL_ID%TYPE
) IS
  V_CNT NUMBER;
BEGIN
  SELECT COUNT(*) INTO V_CNT FROM USERS WHERE USER_ID = P_USER_ID;
  IF V_CNT = 0 THEN
    RAISE_APPLICATION_ERROR(-20003, 'ไม่พบ USER_ID นี้ในระบบ');
  END IF;

  INSERT INTO DIGITAL_BELL_SIGNAL (SIGNAL_ID, USER_ID, SIGNAL_DATE)
  VALUES (SEQ_DIG_SIGNAL.NEXTVAL, P_USER_ID, TRUNC(SYSDATE))
  RETURNING SIGNAL_ID INTO P_SIGNAL_ID;   -- 10g-compatible (ไม่ใช้ SEQ.CURRVAL)

  INSERT INTO VEHICLE_DIGITAL_SIGNAL (SIGNAL_ID, VEHICLE_ID, SENT_AT)
  VALUES (P_SIGNAL_ID, P_VEHICLE_ID, SYSDATE);

  MERGE INTO ALERT_STATISTICS a
  USING (SELECT P_VEHICLE_ID AS VID, TRUNC(SYSDATE) AS D FROM DUAL) s
  ON (a.VEHICLE_ID = s.VID AND a.STAT_DATE = s.D)
  WHEN MATCHED THEN UPDATE SET a.ALERT_COUNT = a.ALERT_COUNT + 1
  WHEN NOT MATCHED THEN
    INSERT (STAT_ID, VEHICLE_ID, STAT_DATE, ALERT_COUNT)
    VALUES (SEQ_ALERT_STAT.NEXTVAL, s.VID, s.D, 1);

  COMMIT;
EXCEPTION
  WHEN OTHERS THEN ROLLBACK; RAISE;
END;
/
  • โครงเดียวกับ SP_PRESS_BELL แต่ตรวจด้วย COUNT(*) (มีคนนี้ไหม → -20003) แล้วเดินสาย junction อีกด้าน (DIGITAL_BELL_SIGNAL + VEHICLE_DIGITAL_SIGNAL) และ MERGE สถิติเหมือนกัน

ก้อนที่ 3–4 · SP_COMPLETE_ALIGHT + SP_CANCEL_BELL — เปลี่ยนสถานะด้วย SQL%ROWCOUNT

oracle_3_plsql.sql · PROCEDURE 3–4 
-- SP_COMPLETE_ALIGHT : คนขับยืนยันว่าผู้โดยสารลงรถแล้ว (SENDING -> SUCCESS)
CREATE OR REPLACE PROCEDURE SP_COMPLETE_ALIGHT (
  P_BELL_REQ_ID IN BELL_REQUEST.BELL_REQ_ID%TYPE
) IS
BEGIN
  UPDATE BELL_REQUEST
  SET NOTIFY_STATUS = 'SUCCESS', ALIGHT_TIME = SYSDATE
  WHERE BELL_REQ_ID = P_BELL_REQ_ID AND NOTIFY_STATUS = 'SENDING';

  IF SQL%ROWCOUNT = 0 THEN
    RAISE_APPLICATION_ERROR(-20002,
      'ไม่พบรายการกดกริ่งสถานะ SENDING ตาม ID นี้ (อาจสำเร็จ/ยกเลิกไปแล้ว)');
  END IF;
  COMMIT;
EXCEPTION
  WHEN OTHERS THEN ROLLBACK; RAISE;
END;
/

-- SP_CANCEL_BELL : ยกเลิกรายการกดกริ่ง (SENDING -> CANCELLED)
CREATE OR REPLACE PROCEDURE SP_CANCEL_BELL (
  P_BELL_REQ_ID IN BELL_REQUEST.BELL_REQ_ID%TYPE
) IS
BEGIN
  UPDATE BELL_REQUEST
  SET NOTIFY_STATUS = 'CANCELLED'
  WHERE BELL_REQ_ID = P_BELL_REQ_ID AND NOTIFY_STATUS = 'SENDING';

  IF SQL%ROWCOUNT = 0 THEN
    RAISE_APPLICATION_ERROR(-20004,
      'ยกเลิกไม่ได้: ไม่พบรายการสถานะ SENDING ตาม ID นี้');
  END IF;
  COMMIT;
EXCEPTION
  WHEN OTHERS THEN ROLLBACK; RAISE;
END;
/
  • เทคนิคเด็ด: เงื่อนไข "ต้องเป็น SENDING เท่านั้น" ฝังใน WHERE ของ UPDATE — ถ้าสถานะไม่ใช่ SENDING แถวไม่ถูกกระทบ → SQL%ROWCOUNT = 0 → โยน error (-20002 / -20004) — ไม่ต้อง SELECT เช็คก่อน 2 รอบ
  • SP_COMPLETE_ALIGHT ยังประทับ ALIGHT_TIME = SYSDATE (เวลาลง — Attribute กำกับความสัมพันธ์ใน ER) ตอนยืนยัน

ก้อนสุดท้าย · Anonymous Block — สาธิต Transaction ต่อหน้าอาจารย์

oracle_3_plsql.sql · ตัวอย่างการเรียกใช้ 
SET SERVEROUTPUT ON

DECLARE
  V_REQ BELL_REQUEST.BELL_REQ_ID%TYPE;
  V_UID USERS.USER_ID%TYPE;
  V_VID VEHICLE.VEHICLE_ID%TYPE;
BEGIN
  SELECT USER_ID   INTO V_UID FROM USERS   WHERE PHONE    = '0800000003';
  SELECT VEHICLE_ID INTO V_VID FROM VEHICLE WHERE PLATE_NO = 'กท 1234';

  SP_PRESS_BELL(V_UID, V_VID, V_REQ);
  DBMS_OUTPUT.PUT_LINE('สร้างรายการกดกริ่ง ID = ' || V_REQ || ' (สถานะ SENDING)');

  SP_COMPLETE_ALIGHT(V_REQ);
  DBMS_OUTPUT.PUT_LINE('ยืนยันลงรถเรียบร้อย -> สถานะ SUCCESS');
END;
/

-- ตรวจสอบผลลัพธ์หลังรัน block ด้านบน
SELECT BELL_REQ_ID, USER_ID, REQ_TIME, NOTIFY_STATUS, ALIGHT_TIME
FROM BELL_REQUEST ORDER BY BELL_REQ_ID;
  • SET SERVEROUTPUT ON — เปิดให้ DBMS_OUTPUT พิมพ์ข้อความออกจอ (ไม่เปิดจะไม่เห็นอะไรเลย)
  • DECLARE 3 ตัวแปร (%TYPE) → หา USER_ID จากเบอร์ + VEHICLE_ID จากทะเบียน (natural key อีกครั้ง) → เรียก SP_PRESS_BELL → เรียก SP_COMPLETE_ALIGHT — เห็นกระบวนการ "กดกริ่ง → ลงรถแล้ว" จบในหน้าจอเดียว
  • ผลที่ต้องเห็น: ข้อความ "สร้างรายการกดกริ่ง ID = 4 (สถานะ SENDING)" แล้ว "ยืนยันลงรถเรียบร้อย → SUCCESS" (ID=4 เพราะ seed ใช้ไป 3) — และผล SELECT ท้ายไฟล์มี BELL_REQ_ID 4 แถว สถานะ SUCCESS พร้อม ALIGHT_TIME

"กรณีนี้คือ Business Rule ที่โจทย์ระบุ → เรา implement เป็น ORA-20xxx ใน Procedure นี้ → ตรวจก่อนเขียนข้อมูล → ผิดแล้ว ROLLBACK ข้อมูลเดิมไม่เสีย — และนี่คือเหตุผลที่ transaction ต้อง ROLLBACK ทั้งก้อน ไม่ COMMIT ครึ่ง ๆ"

❓ Q&A ของหน้านี้ (อาจารย์มักถามตอนรัน PL/SQL)

คำถามคำตอบสั้น
Transaction Processing อยู่ตรงไหน?SP_PRESS_BELL = 3 DML (INSERT BELL_REQUEST + INSERT junction + MERGE สถิติ) ใน 1 transaction — สำเร็จ COMMIT / พลาด ROLLBACK ทั้งหมด (Atomicity)
MERGE ทำอะไร?Upsert สถิติ: ยังไม่มีสถิติของ (รถ, วันนั้น) → INSERT count=1 / มีแล้ว → UPDATE +1 — อาศัย UNIQUE (VEHICLE_ID, STAT_DATE)
Business Rule ในโค้ดมีอะไรบ้าง?กดกริ่งได้เฉพาะ PASSENGER (ORA-20001) · ยืนยัน/ยกเลิกได้เฉพาะสถานะ SENDING (SQL%ROWCOUNT=0 → ORA-20002/-20004)
ทำไมใช้ RETURNING INTO?Oracle 10g ห้าม SEQ.CURRVAL ใน PL/SQL (PLS-00357) — INSERT ... RETURNING คว้า ID ใหม่ได้ทันที ปลอดภัยกับ 10g
SQL%ROWCOUNT ใช้ทำอะไร?เช็คว่า UPDATE กระทบกี่แถว — 0 แถว = ไม่พบรายการสถานะ SENDING → โยน error เอง
%TYPE ใช้ทำไม?ให้พารามิเตอร์/ตัวแปรมีชนิดตามคอลัมน์จริง — แก้ DDL แล้วโค้ดไม่พัง
ทำไมไม่มี Trigger?ระบบนี้คุม flow ด้วย SP เรียกจากแอปชัดเจน (parameter binding กัน SQL Injection) — เหตุผลออกแบบ ไม่ใช่ลืม
ถ้า MERGE พังกลางทางเกิดอะไรขึ้น?EXCEPTION → ROLLBACK ทั้ง 3 DML — กริ่งไม่ถูกสร้าง รถไม่ได้รับ สถิติไม่นับ (ข้อมูลสอดคล้องกันเสมอ)

Q ระหว่าง SP_PRESS_BELL รันอยู่ ถ้า INSERT VEHICLE_BELL_REQUEST (ขั้น 3) ล้มเหลว ผลลัพธ์คือ?

เฉลย: WHEN OTHERS → ROLLBACK — Atomicity ทำให้ 3 DML เป็นเหมือนคำสั่งเดียว: สำเร็จทั้งก้อนหรือไม่มีอะไรเกิดขึ้นเลย
