หน้าแรก • PART II — Smart Bus Bell & IoT Tracking System (อ.ผึ้ง)

🧭 รายงาน SQL 3 แบบ — JOIN 6 ตาราง · สรุปต่อรถ + RANK Analytic · WITH clause

มากสุด 6 ตารางRANK() OVERไฟล์ 4 (Oracle 10g R2)

① อาจารย์ต้องการอะไร (โจทย์ข้อนี้)

"3- เขียน SQL : JOIN แสดงข้อมูลการทำงานหลัก ( JOIN ตารางมากๆ)" — ไฟล์ 4 ตอบด้วย 3 รายงานที่จงใจใช้เทคนิคต่างกันครบ 3 แบบ: รายงาน 1 = JOIN 6 ตาราง (บันทึกการกดกริ่งแบบเต็มสาย), รายงาน 2 = สรุปต่อรถ + อันดับด้วย Analytic Function, รายงาน 3 = รวม Data set ด้วย WITH clause (แทน CREATE VIEW ซึ่ง account ไม่มีสิทธิ์) — รันแล้วผลตรงตามตาราง "ผลที่จะเห็นจริง" ท้ายหน้า

Analytic Function — RANK() OVER (ORDER BY ...) ให้ทั้งรายละเอียดแถว "และ" อันดับในคอลัมน์เดียว (ไม่ต้อง GROUP ทิ้งรายละเอียด) · ค่าเท่ากันได้ rank เท่ากัน (tie)

WITH ... AS (Subquery Factoring) — ตั้งชื่อผล subquery ชั่วคราวเอาไว้ SELECT ต่อใน query เดียว = "view ชั่วคราว" (ทางแก้เมื่อไม่มีสิทธิ์ CREATE VIEW)

LEFT JOIN + NVL — รถที่ไม่มีสถิติเลยก็ต้องโผล่ในรายงาน (ค่า 0 ไม่ใช่หายไป)

📊 รายงาน 1 · ประวัติการกดกริ่งลงรถแบบเต็มสาย (JOIN 6 ตาราง) ⭐

oracle_4_report.sql · รายงาน 1 
-- ----------------------------------------------------------------------------
-- รายงาน 1 : ประวัติการกดกริ่งลงรถแบบเต็มสาย (JOIN 6 ตาราง)
-- ใครกดกริ่ง / บทบาท / รถคันไหน / สายอะไร / สถานะ / สถิติแจ้งเตือนของรถวันนั้น
-- ----------------------------------------------------------------------------
SELECT b.BELL_REQ_ID,
       u.FULL_NAME                 AS PASSENGER,
       ut.ROLE_NAME                AS ROLE_NAME,
       b.REQ_TIME,
       b.NOTIFY_STATUS,
       b.ALIGHT_TIME,
       v.PLATE_NO,
       v.ROUTE_NO,
       s.ALERT_COUNT               AS DAILY_ALERT
FROM BELL_REQUEST b
JOIN USERS u                 ON u.USER_ID        = b.USER_ID
JOIN USER_TYPE ut            ON ut.ROLE_ID       = u.ROLE_ID
JOIN VEHICLE_BELL_REQUEST vb ON vb.BELL_REQ_ID   = b.BELL_REQ_ID
JOIN VEHICLE v               ON v.VEHICLE_ID     = vb.VEHICLE_ID
LEFT JOIN ALERT_STATISTICS s ON s.VEHICLE_ID     = v.VEHICLE_ID
                            AND s.STAT_DATE      = TRUNC(b.REQ_TIME)
ORDER BY b.REQ_TIME;
  • JOIN 6 ตารางเดินลูกโซ่: กริ่ง (b) → ใครกด (u) → บทบาทอะไร (ut) → ส่งให้รถไหน (vb — junction) → รถคันนั้น (v) → สถิติวันนั้น (s)
  • 5 ตัวแรก INNER เพราะเป็นคู่บังคับ (กริ่งต้องมีคน มีบทบาท มีรถผู้รับเสมอ) — แต่ สถิติ LEFT JOIN เพราะวันนั้นรถอาจยังไม่มีสถิติ (ให้ NULL แทนการหายไป)
  • เงื่อนไข 2 ช่องใน ON ของ LEFT JOIN (รถ + TRUNC(b.REQ_TIME) = วันของการกดกริ่งนั้น) — ต้องอยู่ใน ON ห้ามไป WHERE ไม่งั้นกลายเป็น INNER
  • จุดสอน: DAILY_ALERT อ่านว่า "รถคันนี้ วันที่กดกริ่งนั้น ถูกแจ้งเตือนรวมกี่ครั้ง" — สถิติเก็บต่อวัน (UNIQUE รถ+วัน) เลยเทียบด้วย TRUNC

📊 รายงาน 2 · สรุปต่อรถ + อันดับ (Analytic RANK) ⭐ ตัวเด่นสุด

oracle_4_report.sql · รายงาน 2 
-- ----------------------------------------------------------------------------
-- รายงาน 2 : สรุปต่อรถ — ยอดแจ้งเตือนวันนี้ + ยอดสะสมทั้งหมด + อันดับ (Analytic)
-- รถที่ไม่มีข้อมูลเลยก็แสดง (LEFT JOIN + NVL)
-- ----------------------------------------------------------------------------
SELECT v.PLATE_NO,
       v.ROUTE_NO,
       NVL(st.ALERT_COUNT, 0) AS ALERT_TODAY,
       (SELECT COUNT(*) FROM VEHICLE_BELL_REQUEST vb
         WHERE vb.VEHICLE_ID = v.VEHICLE_ID)        AS TOTAL_REQUESTS,
       (SELECT COUNT(*) FROM VEHICLE_BELL_BUTTON vb2
         WHERE vb2.VEHICLE_ID = v.VEHICLE_ID)       AS BELL_BUTTONS,
       RANK() OVER (ORDER BY NVL(st.ALERT_COUNT, 0) DESC) AS RANK_TODAY
FROM VEHICLE v
LEFT JOIN ALERT_STATISTICS st ON st.VEHICLE_ID = v.VEHICLE_ID
                             AND st.STAT_DATE   = TRUNC(SYSDATE)
ORDER BY RANK_TODAY;
  • เริ่มจาก VEHICLE ทั้งหมด (LEFT JOIN) — รถไม่มีข้อมูลเลยวันนี้ก็โผล่ (ALERT_TODAY ผ่าน NVL กลายเป็น 0 ไม่ใช่ NULL) — ตรงคำโจทย์ "รถที่ไม่มีข้อมูลเลยก็แสดง"
  • Scalar Subquery 2 ตัว นับย้อนหลังทั้งหมด (TOTAL_REQUESTS) และนับจำนวนปุ่มที่ติดตั้ง (BELL_BUTTONS — อ่านจาก junction รถ↔ปุ่ม)
  • RANK() OVER (ORDER BY ALERT_TODAY DESC) — ให้อันดับโดยยอดวันนี้มากสุด = 1 · ค่าเท่ากันได้ rank เท่ากัน (tie) แล้วอันดับถัดไปกระโดด
  • เทียบให้อาจารย์ฟัง: GROUP BY จะยุบผลเป็นเลขอย่างเดียว แต่ Analytic ให้ "ทุกคอลัมน์ + อันดับ" พร้อมกัน

📊 รายงาน 3 · Data set รวมด้วย WITH clause (แทน CREATE VIEW)

oracle_4_report.sql · รายงาน 3 
-- ----------------------------------------------------------------------------
-- รายงาน 3 : Data set รวมด้วย WITH clause (Subquery Factoring)
-- หมายเหตุ: account นักศึกษาไม่มีสิทธิ์ CREATE VIEW (ORA-01031)
--           จึงใช้ WITH ทำ "view ชั่วคราวใน query เดียว" แทน ผลลัพธ์เหมือนกัน
-- ----------------------------------------------------------------------------
WITH REQ_REPORT AS (
  SELECT b.BELL_REQ_ID,
         u.FULL_NAME   AS PASSENGER,
         u.PHONE,
         v.PLATE_NO,
         v.ROUTE_NO,
         b.REQ_TIME,
         b.NOTIFY_STATUS,
         b.ALIGHT_TIME
  FROM BELL_REQUEST b
  JOIN USERS u                 ON u.USER_ID      = b.USER_ID
  JOIN VEHICLE_BELL_REQUEST vb ON vb.BELL_REQ_ID = b.BELL_REQ_ID
  JOIN VEHICLE v               ON v.VEHICLE_ID   = vb.VEHICLE_ID
)
SELECT r.*,
       CASE r.NOTIFY_STATUS
         WHEN 'SENDING'   THEN 'กำลังส่ง'
         WHEN 'SUCCESS'   THEN 'สำเร็จ'
         WHEN 'CANCELLED' THEN 'ยกเลิก'
       END AS STATUS_TH
FROM REQ_REPORT r
ORDER BY r.REQ_TIME;
  • WITH REQ_REPORT AS (...)... — ตั้งชื่อผล JOIN 4 ตารางว่า REQ_REPORT แล้วเอามา SELECT ต่อใน query เดียว — ตอบข้อจำกัดข้อ 2 (ไม่มีสิทธิ์ CREATE VIEW)
  • CASE ... END AS STATUS_TH — แปลสถานะอังกฤษเป็นภาษาไทยบนผลลัพธ์ (SENDING=กำลังส่ง ฯลฯ) — อ่าน CASE ว่า "ถ้าค่านี้แล้วแสดงอะไร"
  • ถ้าอาจารย์ถาม "ทำไมไม่สร้าง VIEW จริง" — ตอบ: account ไม่มีสิทธิ์ (ORA-01031) และ WITH ยังดีกว่าในแง่ไม่ทิ้ง object ค้างใน DB
