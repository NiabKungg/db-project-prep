🌱 ไม่มีพื้นฐาน SQL เลย? เริ่มตรงนี้ (อ่าน 5 นาที แล้วไปต่อได้ทั้งเว็บ)

เว็บนี้เขียนให้ "คนที่ไม่เคยเขียน SQL มาก่อน" อ่านแล้วเตรียมสาธิตหน้าอาจารย์ได้จริง — เริ่มจาก 4 ภาพความเข้าใจนี้:

🗄️ ฐานข้อมูล = ตาราง Excel หลายใบที่ผูกกันได้

ตาราง (Table) เช่น DEPARTMENTS มี คอลัมน์ (Column) = หัวข้อข้อมูล (รหัสแผนก, ชื่อแผนก) และ แถว (Row) = ข้อมูล 1 ชิ้นจริง (แผนก IT 1 แผนก)

ตารางผูกกันด้วย "รหัส": PK (Primary Key) = เลขบัตรประชาชนของแถว (ห้ามซ้ำ ห้ามว่าง) · FK (Foreign Key) = คอลัมน์ที่ชี้ไปอ้างแถวของตารางอื่น (เช่น พนักงานเก็บ DEPT_ID แทนการพิมพ์ชื่อแผนกซ้ำ ๆ)

💬 SQL = ภาษาที่พิมพ์สั่งฐานข้อมูล

พิมพ์บรรทัดเดียวแล้วฐานข้อมูลทำให้เอง — ในงานนี้ใช้แค่ 4 กลุ่ม:

  • DDL — สร้าง/ลบโครงตาราง: CREATE, DROP
  • DML — ใส่/แก้ข้อมูล: INSERT, UPDATE, DELETE
  • คิวรี (Query) — อ่านข้อมูลมาแสดง: SELECT
  • TCL — บันทึกถาวร/ย้อนกลับ: COMMIT, ROLLBACK

▶️ คำสั่งแรกในชีวิต (ลองพิมพ์ตามได้เลย)

SELECT * FROM DEPARTMENTS;

แปลว่า "ขอดูทุกคอลัมน์ (*) ของตาราง DEPARTMENTS ทั้งหมด" — ผลที่ได้บนจอ:

และจะให้แต่ละกลุ่มแสดงตาม DB Script และให้ DROP ทุกตารางแล้วสร้างใหม่ ให้ดูแบบ Face-to-face
โดยสมาชิกในกลุ่มต้องเข้าใจทุกเรื่องเหมือนกันครับ
-- **  DB Script ที่ใช้ตรวจสอบผลการทำงาน ** SQL แสดง Object ประเภท TABLE ที่ Database User เป็นเจ้าของ
โดยให้แสดง Constraint ของ Table ดังกล่าวด้วย:
SELECT USER_TABLES.TABLE_NAME, TABLESPACE_NAME, USER_TABLES.OWNER, CONSTRAINT_NAME,
CONSTRAINT_TYPE, USER_CONSTRAINTS.TABLE_NAME
FROM USER_TABLES LEFT OUTER JOIN USER_CONSTRAINTS ON (USER_TABLES.TABLE_NAME = USER_CONSTRAINTS.TABLE_NAME)
ORDER BY USER_TABLES.TABLE_NAME, CONSTRAINT_TYPE, CONSTRAINT_NAME;

🎯 อาจารย์ต้องการอะไร — อ่านโจทย์แตกเป็น 4 ข้อ

  1. DDL + DML ตาม E/R Diagram — ชื่อตาราง/คอลัมน์ต้องตรงกับ E/R ที่กลุ่มส่งอาจารย์ มี Constraint ครบ (PK/FK/UNIQUE/CHECK/NOT NULL) + มีข้อมูลตัวอย่างให้ JOIN ได้จริง
  2. PL/SQL ตามโจทย์หลักของระบบ (Transaction Processing) — โชว์ว่าเข้าใจ COMMIT / ROLLBACK / EXCEPTION และทำงานครบทั้ง Flow ของระบบ ไม่ใช่แค่ SELECT
  3. SQL JOIN แสดงการทำงานหลัก (JOIN ตารางมาก ๆ) — อย่างน้อยมีข้อที่ JOIN 4–6 ตาราง และอธิบายได้ว่าทำไมต้อง JOIN แบบนั้น
  4. DROP ทุกตารางแล้วสร้างใหม่ให้ดู Face-to-face + สมาชิกเข้าใจเหมือนกัน — ต้องซ้อมให้ทุกคนพูดได้ทุกส่วน และจบด้วย DB Script ตรวจสอบ (USER_TABLES + USER_CONSTRAINTS) เสมอ
